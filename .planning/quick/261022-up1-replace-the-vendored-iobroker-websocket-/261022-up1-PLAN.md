<objective>
Swap the hand-vendored ioBroker WebSocket client for its published upstream, and make the broker address the SPA talks to a value configured once in the repo (not per browser), so a locally launched PWA can find the broker.

Two requirements from the description, referenced throughout this plan:

- **UP1-R1** — replace `src/lib/iobroker.socket.io.js` (hand-vendored copy, `// @ts-nocheck`, invisible to `npm audit`, no upgrade path — the recorded debt in `.planning/codebase/CONCERNS.md` and the `⚠️ Revisit` row in `PROJECT.md`) with a standard published package.
- **UP1-R2** — the ioBroker server address gets a configurable fallback, used automatically when the UI is not launched with connection data in the link.

**Decision — which upstream package (deliberate, measured this session, and a documented deviation from the description).**

The description names `@iobroker/socket-client`. Measured facts say that is the wrong package for this substitution:

| Candidate | What it actually is | Verdict |
|---|---|---|
| `@iobroker/ws@3.1.3` | "ioBroker client side of web sockets" (`ioBroker/ioBroker.ws.client`), the browser client the ioBroker web adapter itself serves as `/lib/js/socket.io.js`. **It is the upstream of the file being deleted** — same "ioBroker WebSockets" client, same header lineage (vendored `v 3.0.4 (2025_10_25)` → package `v 3.1.3 (2026_10_04)`), same class and options defaults (ping 5 s, pong 60 s, connect 3 s, 5 attempts). MIT, zero runtime dependencies, npm provenance/SLSA attestation, GitHub-OIDC trusted publishing. | **adopted** |
| `@iobroker/socket-client@5.5.0` | The admin/vis frontend library: `Connection`/`AdminConnection` over the **socket.io** protocol, driven through a global `io` that its own README says to load from the server (`<script src="../lib/js/socket.io.js">`). Its exported `SocketClient` is a **type only** (`export type { … SocketClient }`; `build/esm/SocketClient.js` is 51 bytes). | rejected — adopting it means rebuilding the whole transport (its request/response API, its own caches, token/login flow) and depending on a server-served script. Not a swap; recorded as out of scope, not dropped. |
| `@iobroker/socket-client-backend@5.5.0` | CJS, `dependencies: { ws }` — the Node client. | rejected — not browser-bundleable, pulls `ws` into a static SPA |
| `iobroker.socketio@9.0.2`, `iobroker.ws@5.1.3` | The **server** adapters we connect to (they ship a browser bundle as an example). | rejected — installing a server adapter as a dev dependency is wrong |
| loading the server's own `/lib/js/socket.io.js` at runtime | | rejected — chicken-and-egg for a locally started PWA plus a runtime coupling to the broker origin |

`@iobroker/ws` publishes **no ES exports**: its ESM build ends with `globalThis.io = { connect }`. Its entry point is therefore the side-effect import plus `globalThis.io.connect(url, options)` — which is exactly how the ioBroker admin UI consumes the same file. This is the one structural consequence of the swap (see Task 1).

**Purpose:** close a recorded debt instead of carrying a hand-transformed copy forever, and give the PWA a broker it can find without a per-browser setting.

**Output:** `src/lib/iobroker.socket.io.js` deleted; `@iobroker/ws` in `devDependencies`; `src/lib/broker-config.ts` + a tested URL precedence in `src/lib/socket-url.ts`; `www/` rebuilt and committed; codebase docs, the `PROJECT.md` decision row, and the `REQUIREMENTS.md` INSTALL-06 supersession note refreshed; a human smoke result recorded against the real broker.

**No tracer task (deliberate):** the end-to-end slice already exists and is proven on a real broker — this plan substitutes one component inside it (the transport client) and adds one configuration source. There is no new layer to prove.
</objective>

<assumption_delta_decision>
Signal: `chosen` — the broker address stops being *derived* (the page's host) and becomes *chosen* (a configured value).
Noun that is now primary: **the broker endpoint** ("which broker this SPA talks to"), declared once in `src/lib/broker-config.ts`.
Decision: **promote** — the configured address is the declared default source of the socket URL and of the icon base; the page's own host is demoted to the last resort it already effectively was for a locally started PWA.
Rationale (one line): a single resolution function (`resolveSocketUrl`) names the order, so no caller can hold a competing notion of "the broker".
Invariant test (accepted, in Task 2): the `resolveSocketUrl` cases assert that each source wins **only in its declared slot** — a future caller that derives the broker itself goes red.
