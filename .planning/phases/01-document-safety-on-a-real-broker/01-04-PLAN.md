<objective>
Add the guard that stops a stale `www/` from being committed unnoticed: a source fingerprint recorded in the
built bundle, checked by the build path before Vite overwrites the output.

Purpose: `www/` is committed and shipped (GitHub installs do not build the frontend), so a bundle that no longer
matches `src/` ships a UI nobody reviewed — the concern `CONCERNS.md` carries and PROJECT.md's Key Decisions table
flags as "Revisit". PERSIST-05 requires the build/pack path to report it.
Output: `scripts/build-fingerprint.mjs`, `scripts/www-drift.mjs`, a deterministic `version.name` in
`vite.config.mjs`, a regenerated committed `www/`, and the `prebuild` hook in `package.json`.

**Two facts this plan is built on** (both measured, not read): with the default `version.name` two consecutive
builds differ in exactly `_app/version.json`, `index.html` and `service-worker.js`, because SvelteKit's app prefix
is `hash(kit.version.name)` and the default value is a timestamp; with a fixed `version.name` two consecutive
builds were byte-for-byte identical across all 11 files. And the CI action runs `npm run build` **before** it runs
the unit tests, so any check that runs after the build can never observe staleness — the check must run in
`prebuild`.

**Probe-fallback accounting (spec-less phase).** The edge probe's one PERSIST-05 row (unclassified, unresolved) is
carried verbatim in `must_haves.assumptions` above. The phase-level prohibition list's fifth item is carried here
(`must_haves.prohibitions`); the other four live in 01-01 (1), 01-02 (2) and 01-03 (1).
</objective>

    Create `scripts/build-fingerprint.mjs`: ESM, standard library only (`node:crypto`, `node:fs`, `node:path`), no

    `buildFingerprint()` returning a short hex string: sha256 over each file's relative POSIX path plus its bytes,

    one) to `console.error` before exiting with `process.env.CI ? 1 : 0`; on a match it prints a short OK line and
    exits 0. Read no environment variable other than `CI`, read no credentials (unlike `deploy-www.mjs`, which
    reads `IOBROKER_MCP` — do not copy that line), and write nothing.
    Keep the whole of `scripts/` outside `src/` so `svelte-check` never type-checks a build script as app code.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reviewed source → shipped bundle | `www/` is committed and published; whatever it contains is what an operator's browser runs, whether or not it matches `src/`. |
| build script → credentials/network | A build-time script runs with the developer's environment; it must not gain access to broker credentials. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-11 | Tampering | committed `www/` drifting from `src/` | medium | mitigate | Task 1's guard plus Task 3's demonstrated failure direction: the report is printed before Vite overwrites the output, which is the only moment staleness is observable in CI. |
| T-01-12 | Tampering | a vacuous guard (constant or self-referential fingerprint) | medium | mitigate | `buildFingerprint()` hashes `src/` and `static/` contents and never the bundle; Task 3 proves it moves when a source file changes (see `must_haves.prohibitions`). |
| T-01-13 | Information Disclosure | build script reading broker credentials | low | mitigate | `scripts/www-drift.mjs` is stdlib-only, needs no network, and reads only `CI`; `deploy-www.mjs`'s `IOBROKER_MCP` access is left untouched. |
| T-01-SC | Tampering | npm/pip/cargo installs | low | accept | No packages are installed; the fingerprint uses `node:crypto`. Any new install would need the package-legitimacy gate plus a blocking human checkpoint. |
