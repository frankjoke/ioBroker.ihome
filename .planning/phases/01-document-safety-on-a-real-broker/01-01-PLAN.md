## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| broker state → SPA store | `ihome.0.config.pageList` is read as untrusted input: it can be absent, empty, or unparsable, and the store's reaction to that decides whether the operator's document survives. |
| SPA store → broker state | The only path that overwrites the operator's document; everything this plan asserts lives on this boundary. |
| socket singleton → store | A disconnected socket resolves without sending, so "the write succeeded" is not observable from the promise. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `commitLayout` / `mayWritePages` on an absent or unparsable read | high | mitigate | The guard exists; Task 1 proves it at the store level with zero `setState` on both absent and unparsable reads — this is the incident class that overwrote the migrated documents twice. |
| T-01-02 | Tampering | `savePages` disconnect path | high | mitigate | Task 2 replaces the silent drop with a retry and asserts `getLayoutSaveFailed()` plus an empty `writes` list at flush time; the failure is surfaced, not swallowed. |
| T-01-03 | Tampering | reconnect retry vs a document that changed while offline | medium | mitigate | `flushPages()` re-serialises the current registry and Task 2 Test 3 pins it: the newer document wins, never the pre-disconnect capture (see `must_haves.prohibitions`). |
| T-01-04 | Repudiation | the failure assertion itself | low | mitigate | Task 2 asserts the guard's observable (`getLayoutSaveFailed()`) rather than the promise's settlement, because a disconnected `emitAsync` resolves and would otherwise report a phantom success. |
